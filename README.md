## 一 · 读经之路

### 缘起

禅门标榜「不立文字」，六祖惠能却因闻《金刚经》「应无所住而生其心」言下大悟。不立文字者，非离文字也——文字如指，义如指端之月；因指见月，指非月而不可废。经典俱在，所难者文义之隔：唐宋译语，去今千载，初学者每至卷首而却步。以白话为灯置于侧，照的仍是文字里的义——读原文，参白话，两不相妨。

同作者的姊妹站 [般若藏](https://github.com/wolfpan/fo) 以美术馆陈此四经，供人静观；观者既久，终有愿入文字深处者——于是另起一座**书斋**：原文逐段在前，白话逐段在后，术语点线随文注出，读经一句一句读得进去。

本斋所研，仍是那条路上的脚印：

| 经 | 译 | 读处 |
|---|---|---|
| 般若波罗蜜多心经 | 唐 · 玄奘（T251） | 二百六十言，般若心髓 |
| 金刚般若波罗蜜经 | 姚秦 · 鸠摩罗什（T235） | 五祖印心、六祖悟道之经 |
| 六祖大师法宝坛经 | 唐 · 惠能说 · 元 · 宗宝编（T2008） | 唯一称「经」的中国僧人言教 |
| 楞伽阿跋多罗宝经 | 刘宋 · 求那跋陀罗（T670） | 达磨印心之典 |

界面骨架承 [读通鉴](https://www.dutongjian.com/) 之意：左列经目，中陈正文，右畔诵读。建站之愿，八字而已：**闻思并进，因指见月**。代码以 MIT 协议开源，经文本属公版，白话与释义皆原创编写——皆同法施，取用无碍。

### 用户所见

- **逐段文白对照**：左右并陈、上下叠置、或只读原文、或只读白话，四式随读随换。
- **点线注经**：原文术语着点线下划线，点击出释义卡——术语、人物、地名三类，凡一百零一条。
- **段级工具**：每段可收藏、可贴标签、可看本段术语解、可复制本段链接；收藏按经章归档于书签页，标签可筛。
- **全文检索**：四经原文与白话一处可检，命中高亮，点击直达段落。
- **研读便利**：章节目录树、字号与字体（宋体 / 文楷）、纸色与夜读主题、进度记忆——重访自续前读，首页「继续上次阅读」。
- **静读模式**：隐去左右两栏与滚动条，只留正文；右缘细指示条，滚动方现，止则渐隐——屏息对卷，别无长物。
- **诵读助手**：右栏常驻——学法倒计时（换页、刷新不辍）、显示模式、字号字体、纸色主题、梵音五曲（Web Audio 实时合成，承自般若藏）。

### 前端结构

五页五件，Vite 构建、Vue 3 组合式 API、TypeScript：

```
src/
├── views/        首页 · 经卷页 · 阅读页 · 检索页 · 书签页
├── components/
│   ├── TopBar.vue      顶栏：经目切换、检索入口、静读开关
│   ├── SideTree.vue    左栏：章节目录树
│   ├── ParaBlock.vue   正文段：文白对照、段级工具栏
│   ├── TermPopover.vue 术语释义卡
│   └── ToolsPanel.vue  右栏：诵读助手
├── store/        设置、书签、进度、倒计时（模块级单例 + localStorage）
├── lib/buddha-audio.js  梵音引擎：Web Audio 实时合成五曲
└── styles/
```

无后端；书签、进度、设置皆存 localStorage，访客数据不出浏览器。

## 二 · 技术架构

### 总览

一句话：**Vite + Vue 3 + TypeScript，纯静态，无后端**——经文侧没有数据库，能不引入的都不引入。

| 层 | 技术 | 用途 |
|---|---|---|
| 前端 | Vue 3 + vue-router + TypeScript | 五页路由，阅读页三栏独立滚动 |
| 构建 | Vite（vue-tsc 类型检查） | 纯静态产物，任一静态托管可安身 |
| 数据 | scripts/build-data.mjs | 原文与白话分片 → 逐段对齐 → 全站 JSON |
| 字体 | @fontsource + lxgw-wenkai-screen-web | 宋体 / 文楷 / 行书自托管 |
| 梵音 | Web Audio API | 五曲实时合成，零音频文件 |
| 存储 | localStorage | 书签、进度、设置 |

### 数据管线

```
data/raw/sutras.json        原文（经 → 章 → 段）
translations/<经>/chNN.json 白话译稿分片 {sutra, chapter, start, paras}
glossary.json               术语表
        │  npm run build:data
        ▼
public/data/{index,<经>,search,glossary}.json
```

`build-data.mjs` 校验白话分片与原文**逐段对齐**——断点、越界、缺口，构建期即报错；经与译对得齐不齐由脚本担保，不靠肉眼。检索索引亦在此步预生成，前端只做客户端匹配。若有段落白话未译，以「白话整理中」占位，原文照常可读。

*优势：数据即文件——可 git 追踪、可 diff、离线可用；运行时无数据库，页面加载只是一次 JSON 读入。*

### 梵音引擎

承自般若藏的 Web Audio 实时合成，五曲循环不歇。*优势：零音频资产、零版权问题、零下载流量。*

### 选型之理

1. **读经是慢事**：无登录、无账号、无追踪，打开即读，数据不出浏览器；
2. **对齐即生命线**：文白对照站，最怕经译错位——对齐校验放在构建期，宁可构建报错，不让读者错读；
3. **观读分工**：与般若藏各安其位、互不依赖——观是静看，读是细研，两站各凭本事。

## 三 · 快速运行

```bash
git clone https://github.com/wolfpan/songdu.git
cd songdu
npm install
npm run build:data   # 生成站点数据（public/data/）
npm run dev          # http://localhost:5199
```

生产构建：

```bash
npm run build        # vue-tsc 类型检查 + 产出 dist/
```

`dist/` 为纯静态目录，任一静态托管皆可安身（GitHub Pages / Cloudflare Pages / 对象存储 / VPS）；无环境变量、无数据库。

## 四 · 下一步计划

读有余，思方启。以下数事，皆为补「思」之一环：

- **白话复校**：译文 AI 初成，终须逐段人校——义理处最怕差之毫厘。
- **段间笔记**：书签之外，容读者留一行心得；读完即空，不必成体系。
- **诵读节奏**：「颂读」二字，颂在读写之间——添一逐句缓亮的诵读键，读得慢，方有消化的间隙。
